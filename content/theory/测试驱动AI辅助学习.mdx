# 测试驱动AI辅助学习（TDAA）

## 定义

测试驱动AI辅助学习（Test-Driven, AI-Assisted Learning, TDAA）是一种教学设计模式：取消传统讲授，以高频闭卷测试作为质量门控，同时利用 AI 智能体辅助教师完成学习材料、测试出题、批改等工作流。

## 研究背景

> **来源**: [arXiv:2606.23315](https://arxiv.org/abs/2606.23315)
> **作者**: Jin-Guo Liu, Shang-Qi Lu, Xin-Ran Shi
> **日期**: 2026-06-22
> **课程**: DSAA 3071, Theory of Computation, HKUST(GZ)
> **规模**: 13 周，N=18 学生（proof-heavy 课程）

## 设计模式

### 核心设计
1. **取消讲授** → 学生自主学习 + AI 辅助
2. **高频闭卷测试** → 每周一次，独立完成，作为质量门控
3. AI 辅助材料生产 → 学习路径、课程网站、测试、批改

### 两个关键条件
| 条件 | 作用 |
|------|------|
| 可见的学习路径（学习 sheets + 验证练习） | 闭卷测试感觉公平而非武断 |
| AI 辅助材料工具链（版本控制的 agent 工作区） | 每周起草、审查、出题、批改可规模化 |

## AI Agent 工作流

```
每周循环：
  Agent 起草学习材料 → 教师审查 → Agent 生成测试题 → 学生考试 → Agent 批改 → 教师 oversight
```

- 整个工作流有 git 历史记录，可追溯
- 教师始终保持最终 oversight

## 效果

- 学生认为测试是有用的责任机制（accountability）
- 工作流使高频闭卷测试变得 operational
- 证据来自学生调查（N=18）、每周成绩、git 历史
- **局限**：单课程、无对照组、proof-heavy 课程

## 可复用设计模式

论文将 TDAA 抽象为可复用的设计模式，并开源了 agent 工作区模板：
- 高频测试保持个人 accountability
- AI Agent 使材料生产和批改可规模化
- 版本控制保证可追溯性
